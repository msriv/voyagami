# Translations

All user-facing text lives in `apps/mobile/src/i18n/en.ts`. A lint rule bans string literals in JSX,
so a new string has to be added there first. Plurals use `_one` / `_other` keys; values use
`{{placeholder}}`. Money, dates and numbers go through `@voyagami/locale`, never into strings.

## Adding a language

1. Copy the shape of `hi.ts` (the proof language) to `<code>.ts` and register it in `i18n/index.ts`.
2. Translate. Anything left out falls back to English, so a language can ship a few screens at a time.
3. List the namespaces that are finished in `REQUIRED_NAMESPACES`.

## The check (runs in CI with the app tests)

`src/i18n/__tests__/catalogs.test.ts` fails when a translated catalog:

- has a key English does not have (a typo or a deleted string),
- changes the `{{placeholders}}` of a string,
- is missing a key in a namespace listed as finished.

Hindi finishes `tabs`, `home` and `profile` so far.
